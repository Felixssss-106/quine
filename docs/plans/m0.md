## 模块与依赖

```
app/                    单 Activity、Navigation、主题装配、DI 装配、icon-alias 宿主
feature-onboarding/     首启：接 Key + 选授权目录
feature-chat/           消息流、composer、活动卡、流式渲染
feature-settings/       供应商/Key/模型/连通性 + 外观·应用图标 + 关于
core-design/            双面人 token 层 + 基础组件
core-gateway/           LlmProvider、OpenAI 兼容适配器、SSE、错误映射
core-loop/              Agent 状态机、Flow<LoopEvent>、上下文窗口
core-tools/             工具协议、ToolRegistry、fs_read、JSON Schema 校验
core-storage/           Room + DataStore + Keystore
core-common/            结果类型、错误模型、日志脱敏、Dispatcher
```

依赖规则：`app → feature-* → core-*`；feature 之间不互相依赖；`common ← design/storage/gateway/tools ← loop`；
`core-loop` 不感知 storage（持久化由 app 层接线），保证可用假 provider 单测。

M1 再加入 `feature-tasks/`、`core-sandbox/`、`core-permission/`。

### 本轮新增的决策

| 项 | 决定 | 理由 |
|---|---|---|
| Markdown 渲染 | `multiplatform-markdown-renderer-m3:0.36.0-b02` | 0.36.0-b02 与项目同为 Kotlin 2.2.0；0.39.0 起改用 Kotlin 2.3+ 编译，2.2.0 编译器读不了其元数据（0.38.1 虽可读但编译期对齐的是 Compose 1.9.4，与 BOM 的 1.8.3 方向相反） |
| 等宽字体形态 | 静态三字重（Regular / Medium / Bold），不用变量字体 | 静态字重不依赖 `FontVariation` API，渲染更可预测；体积约 780 KB |
| 中文字形 | 不含 CJK，回落系统字体 | 上游 CN 包约 140 MB，需自行子集化；附录 B 第 5 条仍待定 |
| `Workspace` 的 SAF 还原 | 收进 `core-tools`（`SafWorkspace.fromTreeUri`） | 让 `DocumentFile` 只出现在 core-tools 内部，app 不必认识 SAF 类型 |
| Room 运行时可见性 | `core-storage` 用 `api` 暴露 `room-runtime` | `QuineDatabase` 是公开 API，其父类 `RoomDatabase` 必须一起可见 |
| 工具参数回灌 | 校验失败返回 `ok = false` 的 `ToolResult`，不抛异常 | 错误文本回灌给模型自纠，是 loop 能自我修复的关键 |
| 一轮输出的持久化时机 | 新增 `LoopEvent.AssistantTurn`，在工具结果之前落库 | 否则重开会话时消息顺序会错（assistant 的 `tool_calls` 必须排在 tool 结果之前） |
| 重试归属 | 唯一权威在 loop，装配时 provider 工厂 `RetryPolicy(maxRetries = 0)` | 两层各重试 2 次会把一次请求放大成 9 次 |
| 流式渲染 | ViewModel 内 80ms ticker 节流；`liveAssistantId` 抑制落库与 UI 之间的重影 | 对齐 motion-spec §2.8，且避免同一段文字出现两次 |
| 备份策略 | `allowBackup="false"` + `data_extraction_rules.xml` 全量排除 | Android 12+ 的设备间直传不受 `allowBackup=false` 约束 |

### 本轮修掉的两个既有缺陷

这两个都在上一轮写的 `core-gateway` 测试里，但**因为 CI 命令写错而从未被执行**：

1. `testDebugUnitTest` 只覆盖 Android 模块的 debug 变体；`core-common` / `core-gateway`
   是纯 JVM 模块，测试任务名是 `test`。CI 已改为 `./gradlew lint test assembleDebug`。
2. 跑起来后暴露两处真实 bug：
   - `SseFrameDecoder` 拿 `data.isEmpty()` 当「没收到 data」的哨兵，裸 `data` 字段
     （SSE 规范里合法的空值 data）产不出帧 → 改为单独记录 `hasData`。
   - `OpenAiChunkParser` 遇到坏 JSON 抛 `SerializationException` 而非人话 `LlmException`，
     违反「每个错误必须带下一步动作」→ 统一收敛为 `LlmErrors.malformed()`。

教训记在这里：**质量门命令本身也需要被验证**，否则「CI 绿」是个假信号。
